# Vpered — Arduino Uno firmware

Базовая прошивка для робота **Vpered** (второй робот проекта Samurai).

## Железо

| Компонент | Пины | Примечание |
|-----------|------|------------|
| Мотор L (задний) | PWM1=D5, DIR через 74HC595 | shiftOut DATA=D8, SHCP=D2, STCP=D4, EN=D7 |
| Мотор R (задний) | PWM2=D6 | |
| Клешня (серво) | D11 | |
| Плечо (серво)  | D10 | |
| База (серво)   | D9  | |
| Ультразвук     | TRIG=D12, ECHO=D13 | HC-SR04 |
| Гироскоп       | I2C (A4/A5) | MPU-6050, 0x68 |

WiFi/камеры нет.

## Что делает

1. Калибрует bias гироскопа (робот стоит неподвижно ~0.9 сек).
2. Поднимает серво в безопасную позу.
3. `kickStart()` — импульс PWM=255 на оба мотора 150 мс, плавный спуск до 180.
4. **Автокалибровка знака контроля** (~300 мс): робот делает короткий
   тестовый рывок асимметрией, смотрит куда ушёл θ и автоматически
   устанавливает `controlSign = +1` или `-1`. Это снимает вечную боль
   «робот едет по кругу, потому что GYRO_SIGN не тот» — прошивка
   сама разберётся.
5. Едет вперёд, **держит начальный курс по гироскопу** через PI+D
   (возвращается на 0° при любом отклонении).
6. **Агрессивный режим**: при |θ| > 12° Kp умножается на 2.5 →
   возврат ближайшим путём, без долгого дрейфа.
7. **Watchdog**: если |θ| > 30° полторы секунды → STOP (знак явно
   не сработал — видно в Serial).
8. Останавливается при расстоянии до препятствия < 10 см.

## Контроллер курса (PI+D)

Полная формула:

```
err        = θ_current − 0                     (target = 0)
∫err       += err · dt          (с deadband и anti-windup)
ω_filtered = α·ω + (1−α)·ω_prev (LPF на угловой скорости)

correction = Kp·err + Ki·∫err + Kd·ω_filtered  (clamped ±80)

leftPWM    = BASE − correction   (slew-limited)
rightPWM   = BASE + correction
```

Зачем каждый член:

| Член | Что делает | Без него |
|------|------------|----------|
| **Kp·err** | Возврат пропорционально отклонению | Не возвращается совсем |
| **Ki·∫err** | Устраняет стационарную ошибку (асимметрия моторов) | Стабилизируется не на 0°, а с уводом |
| **Kd·ω** | Демпфирует колебания | Раскачка/виляние |
| **Deadband ±0.3°** | Игнор шума гироскопа на прямой | Моторы постоянно дёргаются |
| **Anti-windup ±60** | Ограничение интеграла при насыщении | Перерегулирование при возврате |
| **LPF α=0.35** | Сглаживание ω для D-члена | D реагирует на шум |
| **Slew-rate ±25** | Плавный возврат | Рывки моторов, нагрузка на драйвер |

## Тюнинг ПИД (порядок)

1. **Поставь `Ki = 0`, `Kd = 0`.**
2. Подними **`Kp`** пока робот не начнёт чуть-чуть колебаться около 0°.
   Возьми `Kp ≈ 0.7×` от этого значения. Стартовое 1.5 — хороший ориентир.
3. Подними **`Kd`** (~0.2…0.5 от Kp) пока колебания не исчезнут.
4. Если робот стабильно едет под небольшим углом (например +2°) —
   подними **`Ki`** малыми шагами (0.05 → 0.10 → 0.15). Слишком большой
   Ki → раскачка с большим периодом (5–10 сек). Тогда уменьши.

В Serial Monitor (9600) видно лог `θ`, `ω`, `I` — следи за поведением:

```
t=2.3s θ=-0.8 ω=1.2 I=-0.45 L=183 R=177 d=120.4
```

- `θ` колеблется в ±1° — норма.
- `ω` стремится к 0 при движении прямо.
- `I` показывает накопленный «trim» от Ki: если он ушёл в +5 и сидит
  там — значит Ki компенсирует постоянный физический перекос.
  При желании можно оттюнить `LEFT_TRIM`/`RIGHT_TRIM` в OPEN_LOOP
  чтобы Ki не нужно было «вытягивать» эту разницу.

## Если всё равно едет по кругу — диагностика

**Новая прошивка сама определяет знак** на старте — посмотри в Serial
строку вида:

```
Auto-calibrating control polarity...
  drift=-3.15° → STANDARD (controlSign=+1)
```

- `STANDARD (+1)` — стандартная схема.
- `INVERTED (-1)` — прошивка развернула знак.
- `WEAK response` — робот плохо повернулся за 250 мс (слишком сильное
  трение / моторы не успели раскрутиться). Увеличь `KICK_MS` или
  попробуй ПОДНЯТЬ шасси так, чтобы колёса крутились свободно, во
  время калибровки — robot just определит знак, потом поставь на пол.

Если после автокалибровки робот всё равно крутится по кругу —
см. шаг 1 ниже. Но это редко.

### Шаг 1. Разомкнутый цикл (физика vs ПИД)

В `vpered_uno.ino` раскомментируй:

```cpp
#define OPEN_LOOP
```

Залей. ПИД отключён, автокалибровка отключена, оба мотора получают
равный PWM.

- **Едет прямо или почти прямо** → проблема была в ПИД. Но автокалибровка
  этого НЕ могла пропустить — значит возможна аппаратная асимметрия
  I2C гироскопа (ось Z плохо реагирует, мусорные значения). Проверь
  монтаж MPU-6050.
- **Крутится в ту же сторону** → физика. См. шаг 2.

### Шаг 2. Подобрать LEFT_TRIM (если перекос механический)

```cpp
const float LEFT_TRIM  = 1.10f;
const float RIGHT_TRIM = 1.00f;
```

- Уводит **вправо** → левый слабее → увеличить `LEFT_TRIM` (1.05/1.10/1.15…).
- Уводит **влево** → увеличить `RIGHT_TRIM`.

Подобрав в OPEN_LOOP — выключи `OPEN_LOOP`, ПИД будет работать на
выровненной базе и Ki будет иметь меньшую работу.

### Шаг 3. Если ПИД нестабилен (виляет)

Уменьши:

```cpp
float Kp = 0.8f;   Kd = 0.20f;   Ki = 0.05f;
```

или временно `Ki = 0` и подбирай Kp/Kd.

## Загрузка

Библиотеки стандартные: `Wire.h`, `Servo.h`.
